## Overview

This track teaches the production operation of inference engines end-to-end for a level-35 specialist in the AI Infrastructure family: positioning on the ladder → inference-engine internals (vLLM, SGLang, TensorRT-LLM, NVIDIA Dynamo, Triton Inference Server) at the depth needed to configure, debug, and SLO-reason about them → request scheduling + continuous batching + chunked prefill → KV-cache management as a runtime concern (PagedAttention, RadixAttention, tiered KV stores with LMCache / Mooncake) → quantization deployment and model-format operations (FP8 / FP4 / INT4 / AWQ / GPTQ / SmoothQuant, safetensors / GGUF / TRT-engines) with accuracy-regression gates → multi-model, multi-tenant, multi-adapter serving (S-LoRA / Punica, cost-aware routing, MIG / MPS / DRA GPU sharing) → distributed inference topologies and disaggregated prefill-decode serving (DistServe / Splitwise / Dynamo) → speculative-decoding deployment and acceptance-rate monitoring → GPU-fleet autoscaling and resilience (K8s HPA on custom inference metrics, Karpenter, warm pools, spot resilience, multi-region failover) → inference-specific observability and SLO engineering (TTFT / TPOT / ITL / cost per 1M tokens, throughput-vs-latency Pareto) → OpenAI-compatible API design and protocols (streaming, structured output, tool calling, MCP server-side) → multimodal, diffusion, speech, and reasoning-model serving → production safety and rollouts specific to inference (canary / shadow / blue-green model swap, inference incident response and runbooks) → cross-functional inference-platform leadership at team scope (build-vs-buy RFC, vendor eval, peer-interface contracts).

It is a **production-serving specialist track at level 35**, positioned in the **AI Infrastructure family**, at the same level as [`ai-infra-performance-learning`](https://github.com/ai-infra-curriculum/ai-infra-performance-learning) (peer specialist — kernel-authoring craft) and [`ai-infra-security-learning`](https://github.com/ai-infra-curriculum/ai-infra-security-learning) (peer specialist — inference-edge security), downstream of [`ai-infra-ml-platform-learning`](https://github.com/ai-infra-curriculum/ai-infra-ml-platform-learning) (level 30, model-registry handoff), [`ai-infra-sre-learning`](https://github.com/ai-infra-curriculum/ai-infra-sre-learning) (level 30, SRE methodology), [`ai-infra-mlops-learning`](https://github.com/ai-infra-curriculum/ai-infra-mlops-learning) (level 25, CI/CD automation), [`ai-infra-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-engineer-learning) (level 20, K8s / cloud base), and [`ai-infra-junior-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-junior-engineer-learning) (level 10, engineering-craft prerequisites). The **single most important peer boundary** in this curriculum is with [`ai-infra-performance-learning`](https://github.com/ai-infra-curriculum/ai-infra-performance-learning) — the two roles share market signal but divide ownership: the performance peer owns the deep optimization *craft* (CUDA kernel authoring, Nsight-to-SASS profiling, Flash Attention / fused-kernel implementation, model-compression algorithm design, CUTLASS / CuTe DSL); this track owns the production *operation* of what the performance peer and the ML-platform peer produce (serving the kernels / quantized models / parallelism topologies in a fleet under SLO, cost, and multi-tenant constraints).

Total planned commitment: **214 hours across 14 modules** + **120 hours across 3 projects** = **~334 hours**.

## Ownership rule

Following the project-wide ownership rule, this curriculum:

- **Owns** the production operation of inference engines end-to-end — inference-engine configuration and operation (vLLM, SGLang, TensorRT-LLM, NVIDIA Dynamo, Triton), request scheduling + continuous batching + chunked prefill, KV-cache management as a runtime concern, quantization deployment with accuracy-regression gates, multi-model / multi-tenant / multi-adapter serving, distributed inference topologies (TP / PP / EP) and disaggregated prefill-decode, speculative-decoding deployment and acceptance-rate monitoring, GPU-fleet autoscaling and resilience, inference-specific observability and SLO engineering, OpenAI-compatible API design and streaming / structured-output / tool-calling protocols, multimodal and emerging-workload serving, production safety / rollout discipline / inference incident response, and the cross-functional inference-platform program at team scope.
- **Defers sideways at the same level (35)** to [`ai-infra-performance-learning`](https://github.com/ai-infra-curriculum/ai-infra-performance-learning) for GPU / CUDA / kernel-authoring / profiling / compression craft — **this is the single most important peer boundary.** Route by primary deliverable: a production serving system → this role; a CUDA / CUTLASS / Triton kernel source file → the performance peer.
- **Defers sideways** to [`ai-infra-security-learning`](https://github.com/ai-infra-curriculum/ai-infra-security-learning) (peer, level 35) for inference-edge adversarial-defence depth (prompt-injection at the API gateway, model-extraction query-rate control, model-weight supply-chain signing).
- **Defers down** to [`ai-infra-ml-platform-learning`](https://github.com/ai-infra-curriculum/ai-infra-ml-platform-learning) (peer, level 30) for the self-service ML platform, model-registry, and training-serving handoff; to [`ai-infra-sre-learning`](https://github.com/ai-infra-curriculum/ai-infra-sre-learning) (peer, level 30) for SRE methodology; to [`ai-eval-engineer-learning`](https://github.com/ai-engineering-curriculum/ai-eval-engineer-learning) (peer, level 30, AI Engineering family) for application-layer eval release-gate contract; to [`fine-tuning-engineer-learning`](https://github.com/ml-engineering-curriculum/fine-tuning-engineer-learning) and [`model-evaluation-engineer-learning`](https://github.com/ml-engineering-curriculum/model-evaluation-engineer-learning) (peers, level 30) for post-training and benchmark methodology; to [`ai-infra-mlops-learning`](https://github.com/ai-infra-curriculum/ai-infra-mlops-learning) (peer, level 25) for CI/CD automation; to [`ai-infra-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-engineer-learning) (level 20) for K8s / Terraform / cloud base; to [`ai-infra-junior-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-junior-engineer-learning) (level 10) for engineering-craft prerequisites.
- **Defers up** to [`ai-infra-architect-learning`](https://github.com/ai-infra-curriculum/ai-infra-architect-learning) (level 40) for cross-stack architecture at team-of-teams scope; to [`ai-infra-team-lead-learning`](https://github.com/ai-infra-curriculum/ai-infra-team-lead-learning) (level 40) for people management; to [`ai-infra-senior-architect-learning`](https://github.com/ai-infra-curriculum/ai-infra-senior-architect-learning) (level 45), [`ai-infra-principal-engineer-learning`](https://github.com/ai-infra-curriculum/ai-infra-principal-engineer-learning), and [`ai-infra-principal-architect-learning`](https://github.com/ai-infra-curriculum/ai-infra-principal-architect-learning) (level 50) for organisation-scope strategy.
- **Out of scope** to the AI Engineering family (`llm-application-developer`, `rag-engineer`, `applied-ai-engineer` at level 25) — prompt engineering, agent design, product analytics — those tracks consume this role's inference API; this role does not deliver the application. Also out of scope: legal / compliance (licensing, data residency, regulator sign-off).

See [`JOB_REQUIREMENTS.md`](JOB_REQUIREMENTS.md) for the requirements-to-coverage map and the cited public references the catalog is grounded in.

## Module summaries

### mod-101 — The Inference Engineer Position on the Infra Ladder
Diagram this role's exact scope on the level ladder — what this track owns vs. `ai-infra-performance` (peer, level 35, kernel-authoring craft), `ai-infra-ml-platform` (peer, level 30, training-serving handoff), `ai-infra-sre` (peer, level 30, SRE methodology), `ai-infra-mlops` (peer, level 25, CI/CD), `ai-infra-security` (peer, level 35, inference-edge security), and the consumer tracks in the AI Engineering family (level 25). Place every major open-source inference engine on a capability map (vLLM, SGLang, TensorRT-LLM, NVIDIA Dynamo, Triton Inference Server, llama.cpp, MLC-LLM; TGI as historical compare-point). Build the vocabulary that anchors the rest of the curriculum (TTFT, TPOT, ITL, E2E, goodput, cache-hit, continuous batching, chunked prefill, prefix caching, PagedAttention, RadixAttention, disaggregated prefill-decode, speculative decoding, TP / PP / EP, LoRA swap, structured output, streaming) and tie each term to the engine primitive. Position the current GPU hardware landscape (Hopper / Ada / Blackwell / GB200 / GB300 / Vera Rubin, AMD MI300 / MI325, AWS Trainium / Inferentia, Google TPU) at operator-depth. Author a "what this platform does and does not do" charter.

### mod-102 — Inference-Engine Internals and Operational Fluency
Read the source of vLLM, SGLang, and TensorRT-LLM to the depth needed to debug a production outage — scheduler loop, KV allocator, model runner, worker-executor layering, request lifecycle. Build and operate each engine end-to-end — vLLM engine args and OpenAI-compatible serve; SGLang RadixAttention tuning, structured-generation front-end, cache-aware routing; TensorRT-LLM convert → quantize → build → serve workflow with Triton Inference Server backend. Characterise the TGI deprecation state. Diagnose common failure modes — OOM on long-context, prefix-cache cliff, allocator fragmentation, CUDA graph recompile storm, torch.compile re-trace, NCCL hang, slow-rank straggler — and apply the right engine knob. **Boundary:** this module reads engines to debug and tune; it does not re-implement the kernels they dispatch to — that is the performance peer at level 35.

### mod-103 — Request Scheduling, Continuous Batching, and Chunked Prefill
Reason about the continuous-batching inner loop (iteration-level scheduling, token-level batching, prefill vs. decode phases, arrival-vs-run queue split, admission control). Author scheduler configurations that hit a stated SLO under a stated traffic shape — max-num-seqs, max-num-batched-tokens, max-prefill-tokens, prefill-chunk-size, scheduler-delay, priority / fairness. Deploy chunked prefill (SARATHI-shape) and reason about the TTFT / TPOT trade-off. Deploy preemption policies (swap vs. recompute, block-level eviction, starvation guards). Instrument the scheduler and feed metrics into SLO alerts (mod-110).

### mod-104 — KV-Cache Management as a Runtime Concern
Reason about PagedAttention at operator depth (block tables, block-size tuning, copy-on-write, allocator fragmentation, block-swap-to-CPU). Reason about RadixAttention at operator depth (radix-tree prefix sharing, cache-aware routing, eviction, TTL vs. LRU). Deploy prefix caching correctly for chat and RAG workloads; measure cache-hit rate and prefix-cache benefit on TTFT. Deploy tiered KV-cache stores with LMCache / Mooncake-shape host-DRAM + NVMe + remote object store. Reason about long-context KV footprint; deploy cross-request KV sharing safely (per-tenant isolation, PII-leakage risk from prefix sharing). **Boundary:** KV allocator *algorithms* and attention-kernel contracts live at the performance peer; KV cache as a *runtime object managed in production* is owned here.

### mod-105 — Quantization Deployment and Model-Format Operations
Deploy FP16 / BF16 baseline, FP8 (E4M3 / E5M2) on Hopper+, FP4 / NVFP4 / MXFP4 on Blackwell+, INT8, INT4, AWQ, GPTQ, SmoothQuant — knowing which engine supports which. Convert and serve safetensors / GGUF / TRT-engines / ONNX and validate conversion fidelity. Author an accuracy-regression gate (tolerance thresholds, canary dataset, perplexity + task-specific metric, bootstrap CI) — deep statistical calibration deferred to `model-evaluation-engineer` (peer, level 30). Author a release contract with `ai-infra-ml-platform` (peer, level 30) for artifact format, metadata, lineage, signing. Reason about AWQ / GPTQ / SmoothQuant / FP8 at operator-depth — algorithm-design depth deferred to `ai-infra-performance` (peer, level 35). Deploy a serving-interruption-free model swap.

### mod-106 — Multi-Model, Multi-Tenant, and Multi-Adapter Serving
Deploy multi-LoRA serving at thousand-adapter scale (S-LoRA / Punica), multi-model co-location on a single GPU for small / cheap models (MIG / MPS / DRA), and cost-aware request routing (LiteLLM-shape) across self-hosted + external providers. Deploy a dynamic weight-loader with eviction. Author a multi-tenant isolation contract (per-tenant SLO, noisy-neighbour mitigation, token-rate limits, prefix-sharing data-boundary). **Boundary:** this module owns the server-side router; application-side provider SDK (OpenAI SDK, LiteLLM client) is at `llm-application-developer` (consumer peer, level 25).

### mod-107 — Distributed Inference Topologies and Disaggregated Serving
Choose and deploy the right parallelism topology at a given model + fleet shape — TP within a node, PP across nodes, EP for MoE, DP attention for small models at high concurrency. Deploy disaggregated prefill-decode (DistServe / Splitwise / NVIDIA Dynamo) with a KV router between prefill and decode workers and cross-node KV transfer. Reason about NCCL collective cost (AllReduce / AllGather / ReduceScatter, NVLink vs. InfiniBand / RoCE / RDMA, overlap-with-compute) at operator depth. Deploy MoE serving (expert parallel topology, token-routing imbalance, DeepSeek V3 / Mixtral / Qwen-MoE deployment patterns). Diagnose scaling cliffs — straggler rank, PCIe-vs-NVLink mismatch, bad placement. **Boundary:** this module operates topologies; the peer *implements* the kernels and tensor-ops those topologies dispatch to.

### mod-108 — Speculative-Decoding Deployment and Operation
Deploy draft-target speculative decoding — pick a draft model, size it against the target, measure acceptance rate per workload. Deploy self-speculative schemes (Medusa, EAGLE, Lookahead) where they beat draft-target. Monitor acceptance rate in production per tenant / model-pair / workload-class and alert on drift. Author draft-model lifecycle (retrain on target drift, versioned-together promotion, rollback). Reason about when speculative hurts latency. **Boundary:** speculative-decoding *kernels* live at the performance peer; draft-model *training* lives at `fine-tuning-engineer` (peer, level 30); this module operates the deployment.

### mod-109 — GPU Fleet Autoscaling and Resilience
Deploy GPU-aware Kubernetes serving (NVIDIA GPU Operator, DCGM-exporter, runtime class, taints, Karpenter / Cluster Autoscaler for GPU bin-packing). Author HPA / KEDA scalers on inference-specific custom metrics (queue depth, in-flight requests, prefill-tokens-per-second, TTFT P99). Deploy GPU sharing where appropriate (MIG hard partitions, MPS soft sharing, DRA flexible scheduling). Design warm-pool / scale-to-near-zero strategies for cold-start-sensitive workloads. Build spot resilience (graceful preemption, in-flight-request draining, checkpointed KV, cross-region failover). Build multi-region / multi-provider resilience (DNS / Anycast / global LB, provider-fallback via LiteLLM-shape router). **Boundary:** general K8s / Terraform / cloud base lives at `ai-infra-engineer` (level 20); this module covers the GPU-specific extensions.

### mod-110 — Inference Observability, SLO Engineering, and Cost per Inference
Instrument an inference fleet with the right axis set — TTFT, TPOT, ITL, E2E, cache-hit, preemption, admission-reject, prefill-decode mix, GPU utilisation (via DCGM), SM activity, memory pressure, NCCL time. Design SLOs for inference-shaped workloads with error budgets at per-token granularity. Build a Prometheus / Grafana / OTel stack specifically for inference. Compute cost per 1M input / output tokens at operator depth (amortised GPU-hour, utilisation-adjusted, prefix-cache credit, speculative-decoding credit). Draw the throughput-vs-latency Pareto curve for a stated model + fleet + traffic shape. Tie inference metrics into business metrics. **Boundary:** SRE methodology depth (incident reporting discipline, error-budget math) lives at `ai-infra-sre` (peer, level 30); this module adopts that methodology for inference signals.

### mod-111 — Inference API Design and Protocols
Implement an OpenAI-compatible API surface — chat completions, responses, embeddings, (images / audio where applicable) — and reason about the compliance-drift tax of "OpenAI-compatible" between engines. Implement streaming at production quality (SSE as primary, WebSocket as alt, chunk-boundary discipline, back-pressure, client-disconnect handling with graceful cancellation). Implement structured output / constrained decoding (JSON Schema enforcement, Pydantic schemas, Outlines / XGrammar backends, grammar vs. regex vs. schema trade-off). Implement tool-calling (tool-choice protocol, parallel tool calls, tool-response round-trip, streaming during tool-call phases). Reason about Model Context Protocol (MCP) on the server side. Author request-shape discipline (retry semantics, idempotency keys, backpressure / rate-limit headers, request-id propagation, auth model, tenant isolation at ingress). **Boundary:** application-side consumer code lives at `llm-application-developer` / `rag-engineer` (peers, level 25).

### mod-112 — Multimodal, Diffusion, and Emerging-Workload Serving
Deploy VLM serving (image preprocessing, visual-token KV cache, per-image token-budget, batching across variable image counts). Deploy diffusion serving (image / video / 3D, step-count control, scheduler choice, denoising-batch patterns). Deploy streaming speech (ASR with streaming decode, TTS with streamed-audio response, chunking and barge-in). Deploy reasoning-model serving (long-think traces, thinking-budget caps, interruptible decoding, structured reasoning-vs-answer channels). Deploy agentic workloads at the serving edge (long-running sessions, tool-call-heavy traffic). Reason about edge / local / on-device inference (llama.cpp / MLX / MLC-LLM / ExecuTorch) at compare-point depth.

### mod-113 — Production Safety, Rollouts, and Incident Response for Inference
Deploy canary and shadow-traffic rollouts specifically for inference (response-diffing with semantic-equivalence tolerance, canary-weight ramp with SLO-based auto-rollback). Deploy blue-green and in-flight model-swap for large models (dual-load constraints, drain-and-swap, atomic routing cutover, model-version header for client observability). Author inference-specific runbooks (TTFT regression, cache-hit cliff, preemption spike, silent accuracy regression, NCCL hang, GPU driver / ECC error, worker crash loop). Run inference incident response (triage, RCA from traces + metric overlays + version diffs, post-mortem, permanent regression-fixture back-feed). Deploy the eval-gate contract with `ai-eval-engineer` (peer, level 30) and `model-evaluation-engineer` (peer, level 30). Deploy a model-deprecation runbook (grace period, consumer migration guide, decommission timeline).

### mod-114 — Cross-Functional Inference-Platform Leadership
Own an inference platform program at team scope — cadence, SLO-review ritual, on-call rotation, deployment-change calendar, migration planning across the ladder of peer tracks. Author an inference-platform RFC with build-vs-buy framing (self-host vs. Fireworks / Together / Baseten / Modal / NVIDIA NIM), total-cost-of-ownership model, risk register, migration path. Run a vendor eval for an inference provider (SLA / price / feature parity / exit cost / data-boundary). Draw the interface contract with the performance peer, the ML platform peer, the eval peer, the SRE peer, and the security peer — explicit role boundaries, mutual deliverables, escalation paths. Position the inference-engineer career trajectory and the load-bearing certifications (NVIDIA DLI, Kubernetes CKA / CKAD, cloud-provider ML cert).

## Assessment

Each module ships **1 quiz** plus the exercises and a lab listed in [`.aicg/curriculum-plan.json`](.aicg/curriculum-plan.json). Each project ships a portfolio-grade README, a reproducibility bundle (engine configs, model / adapter / quantization hashes, load-test traces and reports, SLO dashboards, canary rollout evidence, runbooks, incident-RCA artifacts), and an explicit rubric covering serving-config correctness, SLO achievement, cost accounting, canary / rollback discipline, multi-tenant isolation, cross-peer interface fidelity, and cross-audience communication.
